# Watch2Read

> 将 Bilibili / YouTube 视频转化为结构化的 Markdown 阅读笔记。

**推荐通过 Skill 使用**：让当前 AI 助手完成分段与整理，无需另外配置大模型 API。也保留原有 API 命令行方式，适合批量处理和自动化。两种方式共用文件格式、Markdown 渲染和索引逻辑。

## 为什么做 Watch2Read

深度访谈、技术分享和行业分析往往需要几个小时才能看完，而几百字的摘要又容易丢掉论证、案例和细节。Watch2Read 在「看完整个视频」和「只看一段摘要」之间，提供便于浏览、回顾与检索的结构化长文。

笔记保留关键观点、数据、术语与上下文，按章节和小节组织；每个章节带原片时间戳链接，详细内容可折叠。它不是逐字稿，也不替代原视频中的演示、语气和视觉信息。

## 网页阅读

可通过 [在线阅读页](https://ghy0324.github.io/Watch2Read/) 浏览，也可在仓库根目录运行 `python3 -m http.server 8765`，访问 `http://localhost:8765`。网页直接加载 Markdown 和索引，不需要构建或模型 API。

- 左侧支持按发布日期月份、UP 主分组或不分组；分组可折叠，选择与折叠状态保存在当前浏览器。搜索时显示平铺结果，不会因分组折叠漏掉匹配。
- 右侧目录展开后，可拖动左边缘调整宽度；也支持聚焦分隔条后用左右方向键调整、Home/End 到达边界、双击恢复默认宽度。宽度会记忆，窄屏保持全宽。
- 浏览器缩放和面板宽度变化时，以当前可见文字定位阅读位置，而不是沿用旧的滚动像素。缩放进入窄屏布局时会临时收起左栏，为正文保留空间，返回宽屏后恢复原状态。

## 选择使用方式

| 对比项 | Skill（推荐） | API |
|--------|---------------|-----|
| 使用入口 | 在支持本地技能和文件操作的 AI 助手中提出需求 | 运行 `main.py` / `update.py` |
| 分段与结构化整理 | 由当前助手读取字幕、调用自己的模型能力完成 | 脚本调用配置好的 OpenAI 兼容 API |
| 大模型配置 | 无需单独的 `api_config.json` | 需要 API 地址、密钥和模型名称 |
| 适合场景 | 交互式整理、补充要求、局部重做、个人知识库 | 命令行批处理、定时任务、可控并发 |
| 标准输出 | 同名 `.srt`、`.meta.json`、`.segments.json`、`.json`、`.md` | 相同 |
| README 索引标记 | `skill` | `api` |

**「无需额外 API」不等于免费或离线。** Skill 仍使用当前 AI 助手的模型服务、额度与上下文；下载字幕和元数据也需要网络。API 方式的模型调用由你配置的服务计费。

两种方式遵循同一结构化要求，使用同一 Markdown 渲染器，目标是信息完整程度和阅读体验相似，不保证不同模型、不同运行之间逐字一致。建议每分钟保留约 2–3 个有意义的要点；这是整理目标，不应为了数量补造内容。

## 安装与运行：Skill（推荐）

### 1. 安装到本地

需要 Python 3.10+，以及支持读取本地 `SKILL.md`、运行脚本、读写文件的 AI 助手。

在项目目录执行；还没有项目时，先获取代码：

```bash
git clone https://github.com/ghy0324/Watch2Read.git
cd Watch2Read
python3 scripts/install_skill.py
```

默认安装位置是 `${CODEX_HOME:-~/.codex}/skills/watch2read`。安装器按白名单复制技能、参考文档和运行所需模块，**不复制 API 密钥、已有笔记、Git 历史或缓存**；安装后不依赖原仓库的位置。

为安装后的 Skill 创建独立运行环境并安装字幕依赖：

```bash
SKILL="${CODEX_HOME:-$HOME/.codex}/skills/watch2read"
python3 -m venv "$SKILL/.venv"
"$SKILL/.venv/bin/python" -m pip install requests pycryptodome yt-dlp
```

只处理 Bilibili 时可仅安装 `requests pycryptodome`，只处理 YouTube 时可仅安装 `requests yt-dlp`。需要 PDF 时额外安装：

```bash
"$SKILL/.venv/bin/python" -m pip install markdown weasyprint
```

其他支持 Skill 的宿主可指定其实际的技能目录：

```bash
python3 scripts/install_skill.py --target-dir "/absolute/path/to/skills/watch2read"
```

宿主的发现与加载方式可能不同，请按它的技能加载机制刷新或开启新对话。技能名称为 `watch2read`，入口见 [SKILL.md](SKILL.md)。

### 2. 在助手中运行

在希望保存笔记的工作目录中，直接发送：

```text
$watch2read
请把 https://b23.tv/ELL41Yu 整理为详细阅读笔记。
输出到当前目录的 notes/，保留完整的标准文件，并更新本项目 README 的索引。
```

也可一次给多个链接：

```text
请用 watch2read 处理以下视频，逐个完成，不省略长视频的后半部分：
https://b23.tv/ELL41Yu
https://b23.tv/oaH9JqW
保存到 notes/，需要 PDF，并把索引中的处理方式标为 skill。
```

`$watch2read` 是支持该语法的宿主中的显式技能引用；其他宿主可用自然语言要求使用 `watch2read`。无需自行提供 API 密钥，也不要让助手用标题或简介代替完整字幕。

支持本地字幕输入：

```text
用 watch2read 整理本地 subtitles/interview.srt，
对应视频是 https://www.bilibili.com/video/BVxxxxxxxxxx/。
元数据使用 subtitles/interview.meta.json，输出到 notes/，文件名为「访谈笔记」。
```

本地 SRT 可跳过字幕下载；若同时提供经过核实的元数据 JSON，可跳过元数据获取。仍需视频链接，以便生成时间戳跳转。

### 3. 索引与更新规则

- 默认保存到工作目录的 `notes/`，成功后检查输出目录上一级的 `README.md`。
- README 已含 `<!-- VIDEO_TABLE_START -->` 和 `<!-- VIDEO_TABLE_END -->` 时，自动添加或更新视频行，标记为 `skill`，按发布日期倒序排列。
- 没有 README 或没有上述标记时，默认不修改文档。你可明确要求「为这个 README 建立视频索引」，助手再用 `--readme` 指定目标并添加标记。
- 明确要求「不要更新索引」时使用 `--skip-index`，同时跳过 README 和阅读页文件列表更新。
- 本项目既有 GitHub Pages 笔记链接会保留；其他知识库默认使用相对于 README 的本地 Markdown 链接。
- 相同视频再次生成会更新现有行，不重复追加；「处理方式」记录本次整理使用的方式。历史条目均标为 `api`。

### 4. 修改已有笔记与中断恢复

可以直接提出：

```text
用 watch2read 重新整理这篇笔记的第三章，保留其余章节，
补全论证与案例，仍输出相同格式，并更新 README。
```

Skill 在 `notes/.watch2read/<视频标识>/` 下保留工作文件和逐批结果。中断后要求「继续处理」即可从已有清单与结果恢复，不必重做完成的批次。字幕或分段变化后会使用新的批次版本，不会误合并旧结果。

重做某章时，只替换该章相关批次；重做全部分段时，重新生成批次清单与结果。工作目录丢失但标准文件仍在时，可复用已有 `.srt`、`.meta.json` 和分段信息重建流程。修改已有成品需要明确允许覆盖；助手最后使用 `--overwrite` 写回。API 生成的标准文件也可交给 Skill 继续整理。

### 5. 脚本接口（供助手与调试使用）

通常只需上述自然语言入口。底层脚本不调用大模型 API，而是把下载、校验、分批、渲染等确定性操作交给 Python；分段 JSON 和逐批整理 JSON 由当前助手完成。

```bash
SKILL="${CODEX_HOME:-$HOME/.codex}/skills/watch2read"

# 准备字幕、元数据和概览；终端会输出 WORK=<工作目录>
"$SKILL/.venv/bin/python" "$SKILL/scripts/skill_pipeline.py" prepare \
  -l "https://b23.tv/ELL41Yu" --output-dir notes

# 将上一条输出的 WORK 路径填在这里
WORK="/absolute/path/to/notes/.watch2read/<视频标识>"

# 助手先读取工作文件，按技能要求写入 chapters.json，再执行分批
"$SKILL/.venv/bin/python" "$SKILL/scripts/skill_pipeline.py" split \
  --work "$WORK" --chapters "$WORK/chapters.json" --max-batch-minutes 20

# 助手读 manifest.json，逐个完整读取 batch_file 并写入对应 result_file
# 全部结果完成且校验通过后，发布标准文件并自动更新已有索引
"$SKILL/.venv/bin/python" "$SKILL/scripts/skill_pipeline.py" finalize \
  --work "$WORK"
```

`prepare` 还支持 `--srt`、`--meta`、`--name`；`finalize` 支持 `--readme`、`--skip-index`、`--to-pdf`、`--overwrite`。具体格式、质量要求和检查点见 [Skill 工作流](references/skill-workflow.md)。**仅运行上述三条脚本不会自动完成整理**，中间的助手分段和逐批写入结果不可省略。

多视频可以并行读取和整理，但共用的 README 与 `notes-index.json` 没有跨进程锁，必须由一个协调者逐个执行最终保存和索引更新。子任务如需先生成文件，应使用 `--skip-index`；之后由协调者不带该选项逐个重新执行 `finalize`，内容相同的文件不需要 `--overwrite`。

更新本地安装时，在仓库更新代码后执行：

```bash
python3 scripts/install_skill.py --force
```

已有安装会先备份到技能目录旁的 `.watch2read-backups/<时间戳>/`，再更新打包文件；`.venv` 保留且不进入备份，避免重复安装依赖。未指定 `--force` 时，不覆盖已存在的安装。

## 安装与运行：API

### 1. 安装依赖

API 方式保留原有命令行入口。在项目目录创建环境：

```bash
git clone https://github.com/ghy0324/Watch2Read.git
cd Watch2Read
python3 -m venv .venv
source .venv/bin/activate
python -m pip install requests pycryptodome yt-dlp
```

如已有仓库，只需进入该目录，不必再次克隆。平台依赖可按需安装；PDF 同样需要 `python -m pip install markdown weasyprint`。

### 2. 配置大模型 API

在项目根目录准备 `api_config.json`，使用兼容 OpenAI API 格式的模型服务：

```json
{
  "base_url": "https://your-api-endpoint/v1",
  "api_key": "sk-your-api-key",
  "model": "model-name"
}
```

该文件已列入 `.gitignore`，不要提交密钥或把它写进笔记。API 方式会将字幕及用于分段的元数据发送给配置的模型服务。

### 3. 运行

```bash
# 单个视频，默认保留完整的五类标准文件
python main.py -l "https://b23.tv/ELL41Yu" -c api_config.json

# YouTube
python main.py -l "https://www.youtube.com/watch?v=KcujArdWR8w" -c api_config.json

# 多个视频，默认逐个完整处理
python main.py -l "https://b23.tv/ELL41Yu" "https://b23.tv/oaH9JqW" -c api_config.json

# 流水线模式：跨视频并发执行模型步骤
python main.py -l "https://b23.tv/ELL41Yu" "https://b23.tv/oaH9JqW" \
  -c api_config.json --pipeline --workers 5

# 指定输出名称与目录，仅单视频支持 --name
python main.py -l "https://b23.tv/ELL41Yu" -c api_config.json \
  --name "我的笔记" --output-dir notes

# 使用本地字幕，仍通过视频链接获取元数据
python main.py -l "https://b23.tv/ELL41Yu" -c api_config.json \
  --srt "subtitles/interview.srt"

# 额外输出 PDF
python main.py -l "https://b23.tv/ELL41Yu" -c api_config.json --to-pdf
```

在本仓库根目录运行时，成功生成的笔记会自动加入本 README，处理方式为 `api`。API 入口查找的是**当前工作目录**的 `README.md`，且同样要求索引标记；因此建议始终从项目根目录运行。

### 4. 修改已有笔记

```bash
# 交互式选择视频、章节或小节
python update.py -c api_config.json

# 选择「更新所有视频」时，使用跨视频流水线
python update.py -c api_config.json --pipeline

# 更新时同时导出 PDF
python update.py -c api_config.json --to-pdf
```

首先选择视频：`0` 为全部，`1` 到 `N` 为单个视频。选定视频后，`0` 表示从分段开始完全重新整理，其他编号选择章节；有多个小节的章节还可继续选择只重做一个小节。

脚本复用已有 `.srt`、`.meta.json`、`.segments.json`、`.json`；缺失时会尝试重新获取或生成。Skill 产出的标准文件可被同一入口读取，使用 API 重做后索引标记更新为 `api`。

### 5. API 参数

| 参数 | 说明 |
|------|------|
| `-l, --link` | 视频链接，支持 Bilibili、B 站短链、YouTube；多个链接用空格分隔，必需 |
| `-c, --config` | API 配置文件路径，必需 |
| `--pipeline` | 多视频时按步骤统一推进，模型步骤跨视频并行 |
| `--workers` | 模型调用并发数，默认 5；过高可能触发服务限流 |
| `--max-batch-minutes` | 单次模型处理的目标最大时长，默认 20 分钟，长章节分批后合并 |
| `--srt` | 本地 SRT 文件，跳过字幕下载，仅单视频支持 |
| `--name` | 输出名称，不含扩展名，仅单视频支持 |
| `--output-dir` | 输出目录，默认 `notes` |
| `--to-pdf` | 额外生成 PDF，默认关闭 |
| `--keep-srt`、`--keep-json`、`--keep-meta`、`--keep-segments`、`--keep-all` | 兼容旧命令；现在默认保留全部标准文件，无需额外指定 |

多视频默认执行顺序：

```text
视频 A：字幕 → 元数据 → 分段 → 结构化 → 渲染 → README
视频 B：字幕 → 元数据 → 分段 → 结构化 → 渲染 → README
```

`--pipeline` 则先完成各视频的字幕与元数据，再跨视频并行执行分段和结构化，最后逐个渲染和更新索引。某个视频失败不影响其他视频继续；失败视频不会以不完整结果作为新成品发布。

## 统一输出与格式

**两种方式默认都保留以下五个同名文件**，不再需要 `--keep-all`：

| 文件 | 内容 |
|------|------|
| `{标题}.srt` | 原始 SRT 字幕 |
| `{标题}.meta.json` | 视频元数据：标题、UP 主、发布日期、时长、简介等 |
| `{标题}.segments.json` | 章节分段，含 `source` 和 `chapters` |
| `{标题}.json` | 结构化结果：章节数组，包含 `batch_title` 和 `sections` |
| `{标题}.md` | 带元信息、折叠详情、时间戳链接的 Markdown 长文 |
| `{标题}.pdf` | 可选，由同一 Markdown 导出；两种方式均需额外启用 |

`sections` 中每个小节包含 `title`、`tldr`、`start_seconds` 和 `content` 要点数组。分段来源 `source=meta` 表示从简介或置顶评论提取，`source=llm` 表示由模型依据字幕划分；**这个字段不表示 API 或 Skill**，处理方式记录在 README 的单独一列。

默认文件名从视频标题生成：在冒号处截取，去除非法文件名字符并限制为 100 个字符；也可明确指定 `--name`。不同视频可能得到相同短标题，此时应指定不同名称，避免覆盖。Skill 遇到内容不同的已有成品会拒绝覆盖，只有明确允许更新时才使用 `--overwrite`。

输出示例：

```text
README.md
notes-index.json
notes/
  我的笔记.srt
  我的笔记.meta.json
  我的笔记.segments.json
  我的笔记.json
  我的笔记.md
  .watch2read/            # 仅 Skill 的可恢复工作文件，不是另一种成品格式
```

生成后还会更新输出目录旁的 `notes-index.json`，供已有网页阅读器列出笔记；Skill 显式跳过索引时除外。可恢复工作文件不影响两种方式的成品互通。

本地生成和索引更新不会自动提交、推送或部署 GitHub Pages；线上阅读页需要自行发布后才能看到新笔记。

本仓库默认忽略字幕、JSON 和 Skill 工作缓存的 Git 跟踪，但**忽略不等于删除**，它们仍保存于本地。若需备份或发布这些文件，请按自己的隐私与版本管理策略调整忽略规则。Markdown 笔记及索引仍可正常提交。

## 流程与实现

```text
视频链接或本地 SRT
  → 字幕与元数据
  → 章节分段
  → 分批结构化整理
  → 校验、合并
  → 标准文件与可选 PDF
  → README 和阅读页索引
```

1. **获取输入**：Bilibili 字幕使用 kedou.life 第三方接口，YouTube 使用 `yt-dlp`；优先简体中文字幕，缺失时回退到其他可用语言。只下载字幕，不下载视频。
2. **获取元数据**：读取平台可获得的标题、UP 主、时间、简介与章节线索。可用字段随平台、视频权限和网络状态变化。
3. **分段**：优先使用简介或置顶评论的章节线索，没有时根据字幕主题划分。API 通过模型接口完成，Skill 由当前助手完成。
4. **结构化**：完整读取每个字幕批次，保留观点、论证、案例、数据，去掉口头填充词，谨慎修正识别错误。长章节分批处理后合并回原章。
5. **渲染**：共用 `render_markdown.py`，保证相同的数据结构对应相同的阅读版式；需要 PDF 时调用 `md2pdf.py`。
6. **索引**：共用 README 表格更新逻辑，按视频身份去重、按日期排序，并记录 `api` 或 `skill`。

| 文件 | 职责 |
|------|------|
| `SKILL.md` | Skill 入口、执行约束与宿主工作流 |
| `references/skill-workflow.md` | 文件契约、整理规则、恢复与更新说明 |
| `scripts/install_skill.py` | 白名单安装与更新，不打包密钥或笔记 |
| `scripts/skill_pipeline.py` | Skill 的准备、分批、严格校验、合并、导出 |
| `main.py` | API 主入口，以及两种方式共用的文件名和索引逻辑 |
| `update.py` | API 交互式整篇、章节、小节重做 |
| `download_subtitle.py` | Bilibili / YouTube 字幕获取 |
| `video_meta.py` | 视频链接解析与元数据获取 |
| `segment_video.py` | API 章节提取、语义分段和长章节再分批 |
| `structure_subtitle.py` | SRT 解析、共用结构化提示词、API 调用 |
| `render_markdown.py` | 结构化 JSON 转为 Markdown |
| `md2pdf.py` | 可选 PDF 导出 |

## 限制与排错

- **网页更新后仍显示旧界面**：GitHub Pages 的页面与静态文件可能缓存约 10 分钟。使用浏览器强制刷新（macOS：`Cmd+Shift+R`）；网页内的「刷新列表」只重载笔记，不会更新已运行的网页脚本。
- **无字幕或下载失败**：目前不内置语音转写。可提供合法获取的本地 SRT 后继续；不能仅凭标题或简介编写看似完整的笔记。
- **平台风控与权限**：短链解析、B 站公开接口、kedou.life 和 YouTube 都可能受网络、限流、登录状态或服务变动影响。失败时保留工作文件，如实说明原因，再重试或使用已核实的本地输入。
- **字幕准确性**：自动字幕的人名、数字和专业术语可能有误。上下文修正不能替代事实核实，重要结论请跳转原片确认。
- **长视频与上下文**：必须按批次完整读取字幕，不能用抽样概览代替正文。Skill 的概览仅用于分段，成品整理使用完整批次；工作清单缺少任一结果时不发布不完整笔记。
- **校验不等于内容审核**：脚本可检查结构、必填字段、时间戳和批次完整性，但是否准确保留论证仍需助手自查或人工复核。
- **外部文本不是指令**：视频简介、评论、字幕中的命令或提示词只是待整理资料，不应改变助手的任务、读取密钥或触发额外操作。
- **数据与隐私**：Bilibili 字幕请求经过第三方服务；整理内容会进入所选模型或助手上下文。敏感材料请先确认相关服务的数据政策。
- **PDF 依赖**：WeasyPrint 在部分系统还需系统级渲染库；PDF 失败时先检查依赖，已生成的 Markdown 可继续使用。PDF 是可选输出，不是默认成品完成的条件。
