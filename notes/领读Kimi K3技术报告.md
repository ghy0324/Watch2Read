## 孙宇涛的架构研究：RetNet、YOCO 与循环模型

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=3">为什么请架构研究者领读 K3</a> `00:03`

<details>
<summary>本期以 K3 为入口，沿架构和预训练研究脉络理解十多篇相关工作。</summary>

- 张小珺介绍，Kimi K3 是总参数扩展到 2.8T、全量开源的 MoE 模型，本期希望讲清技术，而非仅罗列跑分。
- 嘉宾孙宇涛是清华大学计算机系博士候选人、上海创智学院璞锐学者，博士阶段主要研究大模型架构与预训练。
- 节目没有在模型发布后立即制作，而是先寻找学术和工作背景合适的领读者；孙宇涛会把 K3 放回相关论文的连续发展中解释。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=149">架构研究从性能导向转向效率导向</a> `02:29`

<details>
<summary>孙宇涛关注的核心是降低推理成本，让模型真正部署得起。</summary>

- 孙宇涛从 2023 年开始博士课题，团队的架构探索在 ChatGPT 发布前后就已展开，近两三年的重点是推理环节的低效。
- 他认为，ImageNet 时代常靠精巧架构提升任务表现；在大模型时代，参数规模成为能力的重要决定因素，局部结构改动的能力收益相对较小。
- 不同架构的推理效率却可能差别巨大，这会直接影响最终部署价格，因此研究重心逐渐转向效率。
- 这并不意味着不追求能力，而是要求架构在保持能力的同时，改善存储、计算或硬件执行效率。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=242">RetNet 的第一步：给有限状态加入衰减</a> `04:02`

<details>
<summary>衰减让线性注意力更重视局部信息，提高有限状态空间的利用效率。</summary>

- 早期线性注意力尝试用线性 kernel 近似二次复杂度的全注意力，但位置信息敏感性不足。
- 线性注意力虽然在计算形式上类似 RNN，建模特性却未必具有 RNN 对局部性的强调。
- RetNet 较早引入衰减机制，使有限状态空间更偏向保留对当前结果贡献较大的信息。
- 它要解决的不只是复杂度问题，也要让线性注意力在一般场景中的表现尽量接近全注意力。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=305">Chunk-Wise Recurrent：算法复杂度与 GPU 效率一起考虑</a> `05:05`

<details>
<summary>块内并行、块间递归，是线性注意力兼顾复杂度和硬件利用率的关键。</summary>

- 逐 token 递归虽然有线性复杂度，却难以充分利用 GPU；完全照搬全注意力的并行计算形式，又会失去复杂度优势。
- RetNet 在两者之间提出块递归计算：保留整体复杂度收益，同时提高局部计算密度。
- 这种形式让 kernel 能尽量利用 Tensor Core，而不是只在纸面上减少运算次数。
- 孙宇涛指出，后续 Mamba 2、Gated DeltaNet、Kimi Linear/KDA 等工作都在这一计算大框架上继续改进。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=385">为什么转向混合注意力</a> `06:25`

<details>
<summary>混合注意力是工程折中，但不必然以能力损失换速度。</summary>

- 孙宇涛回顾，纯线性注意力的有限状态难以在长上下文中完整匹敌全注意力，团队在 2023 年便注意到这一限制。
- 混合注意力把线性注意力层与全注意力层组合，K3 也采用这一路线。
- 实验中，只要保留一定比例的全注意力，混合模型可以获得近乎无损、甚至更好的长上下文表现。
- 因此它不是简单牺牲能力换取工程收益，这一经验结果推动了混合架构的大规模采用。
- 但若全注意力占四分之一，单纯替换其余层带来的加速仍受常数因子限制；孙宇涛以常见 3:1 配比说明，理想上限约为四倍，并非无限增长。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=533">YOCO：不能省 token，就从层间省 KV Cache</a> `08:53`

<details>
<summary>共享一份缓存，把注意力计算能力与缓存存储量解耦。</summary>

- YOCO 从基本需求出发：若模型需要访问全文信息，就难以完全去掉覆盖全部上下文的 KV Cache。
- 既然不能沿 token 长度维度继续压缩，团队转而沿层维度节省，让多个层共用一份 KV Cache。
- 共享缓存不等于只做一层注意力计算；模型仍可保留多层全注意力计算，从而保持长上下文能力。
- 在 prefill 阶段，主要目标是获得用于后续解码的缓存，不必为输入中的每个位置都生成下一 token。
- 因此 YOCO 可以先用前部线性注意力计算得到缓存，在 prefill 跳过后部 cross-attention；decode 时再执行所需注意力计算。
- 孙宇涛认为，在仍需保存全文信息的前提下，一份 KV Cache 已接近这一维度上的存储下限。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=679">循环模型的问题与 YOCO 上的改进</a> `11:19`

<details>
<summary>把循环放在线性注意力部分，才能避免参数省了、推理成本却失控。</summary>

- 孙宇涛把主要推理瓶颈分为 prefill 时间、decode 时间和 KV Cache 存储；YOCO 主要解决前者与缓存，并未自动解决 decode。
- 传统 Looped Language Model 保持参数规模不变，通过重复迭代增加计算量，争取比同参数模型更强的能力。
- 但循环只省参数、不一定省计算；相同计算预算下，未必优于展开参数后的更大非循环模型。
- 传统循环模型还会随有效推理深度增加 KV Cache，导致解码和存储成本都很高。
- YOCO 的混合结构不是层间交错，而是前段线性注意力、后段全注意力；后续工作据此只循环前段。
- 线性注意力的状态存储小，长上下文下的额外计算也较少，使循环的存储代价可控。
- 孙宇涛介绍，其实验可用约两倍计算换取相应能力提升，同时让模型参数与 KV Cache 存储仍接近原模型；这是特定架构实验结论，不是所有循环模型的通用保证。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=897">架构创新为何适合博士研究</a> `14:57`

<details>
<summary>有价值的架构工作往往需要与 Infra 协同，而不只是修改数学表达式。</summary>

- 孙宇涛认为架构研究有趣，好的设计能够以较小改动带来明显效率收益，适合作为博士研究方向。
- 架构仍需工程配合，但其工程重点常是与 Infra 的共同设计；块递归形式本身就是这种协同创新。
- 从行业需求看，全注意力曾是大规模推理部署的重要瓶颈，既必须解决，也有可探索的技术空间。
- 他同时提醒，这是对 2023 年机会的回顾；到 2026 年，自己感到大模型架构可做的重大改进空间正在收窄。

</details>

## 从线性注意力到 Kimi Delta Attention

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=1306">复杂公式是历史改进的叠加</a> `21:46`

<details>
<summary>KDA 每个项都有来历，应从最简单的线性注意力逐步理解。</summary>

- 直接看 Kimi Delta Attention 的长公式，很难知道每项的作用；孙宇涛建议回到过去三四年的发展过程。
- 最早的线性注意力可以直观理解为把 K、V 的外积累积到状态中，其表达比 RetNet 还简单。
- RetNet 加入与相对位置相关的衰减，使模型从缺乏位置敏感性的形式变为能区分远近。
- 语言通常更依赖邻近内容，有限状态下引入衰减能够改善信息分配；这一经验随后被多项工作保留。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=1404">线性复杂度为什么不自动等于训练更快</a> `23:24`

<details>
<summary>必须找到适合 GPU 的计算形式，才能兑现算法优势。</summary>

- 完全递归的训练计算可能非常慢，甚至慢于类似全注意力的并行形式。
- 完全并行展开又可能与全注意力具有相同计算量，额外处理和不成熟 kernel 还会使它更慢。
- 因此仅论证复杂度下降不够，还必须同时发挥 GPU 的计算能力。
- Chunk-Wise Recurrent 的目标就是在这两种极端之间取得可用平衡，为后续线性注意力提供可高效实现的框架。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=1464">Mamba、DeltaNet 与两条研究路线</a> `24:24`

<details>
<summary>一条路线接受纯线性注意力的限制，另一条继续提高其状态容量。</summary>

- RetNet 之后，Mamba 在衰减机制上进一步引入随输入变化的选择性，而不再只用固定的衰减形式。
- DeltaNet 的思想并非后来工程实现者首次提出，关键后续工作是把它转化成 GPU 可用的块递归并行计算。
- 面对线性注意力的长上下文不足，孙宇涛当时更倾向于转向混合架构；另一条路线则继续提升纯线性注意力的有效容量。
- DeltaNet 希望在相同状态或缓存大小下，用更好的更新算法保存更多上下文信息。
- 这一路线同时需要解决表达能力和并行实现，不能把算法进展与 Infra 工作割裂。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=1568">Gated DeltaNet 把容量与衰减结合</a> `26:08`

<details>
<summary>Delta 更新提高容量，衰减帮助管理历史信息，两者可以叠加。</summary>

- 早期 DeltaNet 没有引入位置衰减，在 perplexity 或 benchmark 上的表现仍有不足。
- 既然衰减已被证明有帮助，自然可以把它与 DeltaNet 更高容量的状态更新结合。
- Gated DeltaNet 正是把这两类机制合并，从而得到更强的线性注意力表达。
- 在递归公式中去掉衰减项，可以退回 DeltaNet；进一步去掉相应更新系数，又能看到更简单线性注意力的形式。
- 公式逐步变长并非随意堆砌，而是过去不同能力缺口的修正累积。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=1656">KDA 的核心：从标量衰减到逐通道衰减</a> `27:36`

<details>
<summary>更细粒度的控制扩大表达能力，但也增加 kernel 实现难度。</summary>

- 此前许多线性注意力方案在同一 head 内采用统一标量衰减，整个 head 的各通道共享一个系数。
- 标量形式容易实现：在一个计算 tile 中处理少量控制变量即可，便于利用 Tensor Core。
- KDA 把衰减改为 channel-wise 的细粒度控制，让同一 head 内不同通道具有不同衰减速度。
- 逐通道形式可以退化为统一标量形式，因而在表达空间上包含旧方案；孙宇涛据此解释其能力上限更高。
- 但表达空间更强并不是无成本收益，更细粒度的系数会让高效 kernel 的组织与数值处理复杂得多。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=1787">为什么引入有下界的衰减</a> `29:47`

<details>
<summary>衰减边界既限制忘记速度，更重要的是保证低精度高效计算的数值范围。</summary>

- 从算法直觉看，可以希望状态不要衰减得过快；但论文中的 lower-bounded decay 更直接服务于模型与 kernel 的共同设计。
- 为把递归关系改写为高效并行形式，可以像 RoPE 用绝对位置表示相对位置那样，将相对衰减拆成 Q、K 两侧的绝对变换。
- 这种变换利用乘法结合律得到等价计算，但一侧可能需要除以很小的数，产生数值范围问题。
- 仅乘小数会趋向零，取倒数则可能变得过大；两种极端都要在 BF16 可表示范围内控制。
- 因此衰减不是任意选择的超参数，而需结合 tile 长度与目标精度，给出明确约束。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=1898">用 16-token tile 反推安全范围</a> `31:38`

<details>
<summary>KDA 的最终形式是表达能力与硬件数值约束共同塑造的。</summary>

- 孙宇涛以 16-token tile 为例：BF16 的动态范围已知，可以反算这一窗口内允许的最大衰减程度。
- 限制衰减后，可以保证 tile 内的相关变换不超出数值范围，使高效 kernel 的实现更顺畅。
- 不限制衰减也不是完全无法实现，但通常需要更复杂或更低效的处理。
- 他将 KDA 概括为两步：先扩展 Gated DeltaNet 的表达能力，再为新增的实现困难施加合理约束，最终形成 K3 所采用的结构。

</details>

## Gated MLA：稳定性、计算与带宽的取舍

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=1998">为什么 K3 继续使用 MLA</a> `33:18`

<details>
<summary>在已验证可用的全注意力部分保留 MLA，再补上门控带来的稳定性。</summary>

- MLA 最初在 DeepSeek-V2 中用于降低 KV Cache 开销，随后被 DeepSeek-V3 和 Kimi K2 采用。
- K3 在全注意力部分继续沿用 MLA，孙宇涛将其理解为保留已经可用、没有必要大幅改动的方案。
- K3 增加了来自 Gated Attention 研究的门控操作，把两种相对独立的设计组合起来。
- 门控论文讨论非线性、稀疏性和 attention sink 等作用；孙宇涛最强调的实际价值是训练稳定性。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=2062">稳定性比小幅能力优势更重要</a> `34:22`

<details>
<summary>超大规模训练最怕整次训练失效，因此少量额外开销可以接受。</summary>

- 在大规模预训练中，团队希望训练能够稳定进行很长时间；架构小幅能力差异未必比稳定性更重要。
- 一次严重失稳可能使整次 run 和前面积累的 checkpoint 失去价值，这是团队难以承受的损失。
- 门控虽增加一定计算量，但如果能显著改善稳定性，就有很强的采用动机。
- Gated Attention 与 GQA、MLA 等注意力形式并不冲突，K3 因而可以在不破坏 MLA 主要推理性质的前提下加入门控。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=2168">MLA 不是必然成为共识的终点</a> `36:08`

<details>
<summary>它是存储和计算之间的一种折中，收益未必不能被其他参数配置实现。</summary>

- 被问及 MLA 是否会成为未来共识，孙宇涛从技术角度指出，它可转化为一种等价的较大 MQA 形式。
- 他认为 MLA 为达到类似建模效果，可能增加注意力计算，而合理设计 GQA 参数也可能拿到其大部分收益；这是嘉宾的判断。
- 他解释 DeepSeek 后续转向稀疏注意力时，MLA 与稀疏化并非完全兼容，尤其在 prefill 阶段，因此设计会发生变化。
- 在他的表述中，MLA 始终只是一个选择，而不是业内已经统一的最终方案。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=2245">MLA 与 MTP 的收益为什么可能重叠</a> `37:25`

<details>
<summary>两者都试图利用带宽受限时的闲置计算，所以不能简单叠加加速比。</summary>

- 张小珺转述罗福莉的观点：MLA 面向当时 H 系列芯片的计算与访存比例设计，对聊天可能合适，但未必最适合 Agent。
- MTP 同时处理更多 token，把 memory-bound 的执行向更充分利用算力的方向推进。
- 若 MLA 本身已经用额外计算换取访存改善，留给 MTP 的同类收益空间就会变小，两者不是完全正交的加速机制。
- 孙宇涛认为 K3 保留 MLA 在工程和项目管理上合理：能跑通且不是主要瓶颈的部分，未必值得同时重做。
- 他不排除未来继续替换 MLA，并再次强调门控的稳定性收益独立于是否选择 MLA。

</details>

## Attention Residuals 与残差连接的演进

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=2357">连接方式与训练稳定性的历史</a> `39:17`

<details>
<summary>Attention Residuals 延续了 ResNet 以来对深浅层连接和稳定性的探索。</summary>

- 这一研究线关注深层模型如何使用浅层信息，与 ResNet 解决模型加深后性能退化、改善稳定性的目标一脉相承。
- 孙宇涛指出，归一化放在残差分支的什么位置，早期视觉网络研究已讨论过，并非大模型时代才出现的问题。
- BERT 时代常使用 Post-LN，部分实验效果较好；但规模加大后，梯度与训练稳定性问题促使业界更多转向 Pre-LN。
- Attention Residuals 不能简单理解为移动 LayerNorm 位置；大规模训练不愿重新承担 Post-LN 的风险。
- 他强调这类设计应包含可退化为 Pre-LN 的情形，在保留已有可靠结构的同时扩展表达能力。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=2483">Hyper-Connections 的核心是增加残差容量</a> `41:23`

<details>
<summary>用更大的残差状态承载跨深度信息，是后续连接创新的重要起点。</summary>

- 孙宇涛高度评价 Hyper-Connections，认为其本质是在 Pre-LN 基础上扩大残差分支容量。
- 残差分支可以比模型单层 hidden state 更宽，从而更充分地表示模型沿深度演进的状态。
- 他认为该思想本身简洁，但原论文表达较抽象，增加了阅读和传播门槛。
- 后续 mHC 等工作更受关注，他认为品牌影响力也是原因；技术归属仍应回溯到早期 Hyper-Connections。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=2555">为什么几乎不增加推理成本很重要</a> `42:35`

<details>
<summary>架构收益必须与直接增大模型这一简单基线比较。</summary>

- Hyper-Connections 和 Attention Residuals 的吸引力之一，是在推理阶段几乎不增加开销，却能改善模型效果。
- 若一个结构靠更慢的实现或更多计算提升能力，就必须回答：为何不直接把模型参数做大？
- 这种近乎免费的改进更容易被保守团队采用，因为不必显著改变部署成本。
- 因此评价创新不能只看效果提升，还要看是否引入新的速度与能力折中。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=2615">从 DenseNet 到跨深度 Attention</a> `43:35`

<details>
<summary>让深层访问所有浅层状态并不新，新的机会在于更轻量地实现聚合。</summary>

- 孙宇涛将 DenseNet 视为不可绕过的前史：它让深层查看并聚合此前多个浅层状态，而非只有相邻层残差相加。
- 早期 DenseNet 主要依赖较重的线性聚合结构，连接本身会增加明显计算成本。
- Attention Residuals 用注意力式聚合替换其中较重的部件，使类似思想可以更轻量地落地。
- 这也是为什么孙宇涛从创新源头角度更偏爱 DenseNet 和 Hyper-Connections：前者早早提出了关键问题，后者在 Transformer 时代重新激活了这条路线。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=2685">Block Attention Residuals 的能力与成本折中</a> `44:45`

<details>
<summary>分块切断开销随深度增长的压力，同时保留大部分收益。</summary>

- 若上层直接与所有下层状态交互，模型越深，连接开销就越难忽略。
- Block Attention Residuals 通过分块方式弱化对总深度的依赖，配合轻量注意力计算降低额外成本。
- 分块形式在严格表达能力上不及完整跨层注意力，但论文报告其损失较小、相对基线的收益仍明显。
- K3 基本沿用了此前相关技术论文中的设计，孙宇涛没有把它描述为 K3 报告中另起炉灶的新方案。
- 他承认后续工作在稳定性和 Infra 协同上有实际价值，同时强调大的思想框架来自前人积累。

</details>

## LatentMoE：从架构上降低通信成本

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=2783">MoE 的瓶颈不仅是算专家</a> `46:23`

<details>
<summary>All-to-all 分发会影响速度，也会反过来决定底层工程方案。</summary>

- 孙宇涛介绍 LatentMoE 来自英伟达团队的工作，针对的是 MoE 训练与推理中重要的通信成本。
- 在专家并行 EP 下，hidden state 要发给不同 GPU 上的专家，all-to-all dispatch 的开销很大。
- 通信量随激活专家数量和 hidden state 维度增长，这也是 DeepEP 等高性能通信库的重要动机。
- MoE 架构的不同选择，不仅改变模型本身，还会影响 Infra 的通信、并行和调度设计。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=2834">先压缩通信表示，再补回表达能力</a> `47:14`

<details>
<summary>降低分发维度不必简单等于缩小模型，容量可通过专家配置重新分配。</summary>

- LatentMoE 先把要 dispatch 的 hidden state 投影到较低维空间，例如降低两倍或四倍，减少传输数据。
- 直接降低维度会改变专家参数容量，因此要通过配置补偿，而不能只缩小表示就结束。
- 一种补偿方式是增大 FFN 的 intermediate dimension，补回下降的参数规模。
- 另一种方式是进一步细分专家，使用更多专家及更多激活来恢复容量。
- 孙宇涛引用论文结果称，恰当配置的 LatentMoE 可以保持甚至略优于标准 MoE 的效果，同时显著减少通信。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=2929">为什么推理延迟的收益更直接</a> `48:49`

<details>
<summary>训练可隐藏一部分通信，但推理关键路径上的时间很难完全消失。</summary>

- 训练主要追求总吞吐，可以把通信与计算重叠，以降低通信暴露在总时长中的比例。
- 推理延迟更受关键路径影响，即便能做一定重叠，真实的通信时间仍难完全消除。
- 因此孙宇涛认为 LatentMoE 对推理延迟的价值可能比对训练吞吐更大。
- 若保持模型能力而降低通信，就接近免费的效率收益；K3 采用了这条路线。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=2981">两个线性层可合并，不代表优化性质相同</a> `49:41`

<details>
<summary>低维投影引入的连续矩阵乘，需要归一化来控制中间状态。</summary>

- 两个矩阵连乘在表达上可合成一个矩阵，但拆开训练与直接训练合并矩阵并不具有相同优化性质。
- 连续线性投影容易出现训练不稳定，通常需要在中间加入 normalization 等措施。
- MLA 先降维再投影回去，已有类似问题和处理思路。
- LatentMoE 的降维投影之后，FFN 起始处又是线性投影，形成连续矩阵乘；K3 通过 RMSNorm 约束中间 hidden state。

</details>

## 激活值控制、专家均衡与原生视觉编码

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=3074">从硬截断到平滑有界激活</a> `51:14`

<details>
<summary>约束 FFN 中间激活，是提高低精度训练稳定性的直接办法。</summary>

- 大模型 FFN/MLP 中间 hidden state 容易出现 activation outlier 或数值爆炸，这与优化器和计算精度都有关系。
- 精度越低，极端激活越容易成为问题，因此必须控制中间数值范围。
- 孙宇涛以 GPT-OSS 的 clamped SwiGLU 为前例：直接对无界部分做 clip，可以从数学上给出上界。
- 把硬截断改成平滑截断，可以自然想到 tanh 形式，让数值平滑逼近给定边界。
- K3 的相关激活设计对中间可能无界的部分做有界变换，使 MLP 激活得到明确范围。
- 他把这理解为 clip 的平滑升级，但强调其具体能力收益需要实验验证，不能仅凭形式推断。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=3199">Muon 与 outlier：不要把推测当成他人原话</a> `53:19`

<details>
<summary>优化器可能改变问题出现的速度，严格保证仍需来自架构约束。</summary>

- 孙宇涛观察到 Muon 训练中更容易出现 outlier，因此认为控制中间激活是合理措施。
- 他随即说明，自己推测苏建林会反对把问题简单归因于 Muon；这不是苏建林在本次讨论中的实际发言。
- 他回忆此前关于 MuonClip 的讨论：即便 Adam 在某次训练中看起来稳定，也不意味着从数学上保证不会出现异常值。
- 如果某种无界行为在结构上可能发生，区别可能只是出现早晚；从架构层面约束它，比仅调整优化细节更本质。
- 这一讨论的共同落点不是给优化器贴好坏标签，而是让模型具有更可靠的数值边界。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=3296">从 weight decay 到 QK-Clip</a> `54:56`

<details>
<summary>注意力和 MLP 都要控制异常值，但具体手段受架构兼容性影响。</summary>

- K3 的 Muon 方案总体延续 K2，没有在这里重新设计一套完全不同的优化器。
- 孙宇涛回顾，早期 Muon 版本较粗放，甚至未加入 weight decay；Moonlight 将相关措施带入更大规模、更长时间的训练。
- K2 又在此基础上加入针对 QK 的 clipping，形成更完整的稳定性处理。
- QK normalization 可以直接限制 QK 数值，但在 MLA 中不能简单照搬，因此 Kimi 采用适配 MLA 的 QK-Clip。
- 采用 GQA 等其他形式的模型可以选择更直接的 QK norm；不同团队方法不同，目标都是约束异常值。
- QK 之外，MLP 同样可能产生 outlier，K3 因而又通过有界激活函数控制这一部分。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=3394">Quantile Balancing 想修正什么</a> `56:34`

<details>
<summary>从经验性 bias 更新，转向更有数学依据的专家负载均衡。</summary>

- Quantile Balancing 的相关思想由苏建林在技术博客中解释，可沿着 loss-free 路由均衡的研究线理解。
- Loss-free 方法主要调整路由 bias，而不依赖一个全局辅助均衡 loss，来改变 token 选择专家的倾向。
- 原有更新规则较启发式：专家被激活太多就降低 bias，被激活太少就提高 bias。
- 孙宇涛指出，这种方法虽有效，但更新缺乏明确的收敛解释，且底层若干层可能难以均衡。
- 一些模型把最前面一层或三层改成 dense，不用 MoE；他认为这是特定均衡方法下的工程补偿，不是底层天然必须为 dense。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=3475">直接求 bias，下一步再使用</a> `57:55`

<details>
<summary>更精确的均衡目标需要避免跨 token 信息泄漏，也减少了调参负担。</summary>

- Quantile Balancing 尝试通过更原则化的推导求出 bias，而非仅靠反复手调的启发式步长。
- 对某一步整体的激活分布，可以计算一个使负载趋向均衡的 bias，其思路与 Expert Choice 有关联。
- 为避免当前 token 通过路由更新获得其他 token 的信息，求出的 bias 不用于当前 step，而在后续 step 使用。
- 相比 loss-free 原有类似学习率的 bias 更新，它减少了一个需要调节的参数。
- 这种方法能改善原先难以处理的第一层均衡，减少必须将底层改为 dense 的需要。
- 他补充，使用辅助 loss 的方案也可以解决第一层问题，因此不能把所有旧模型的设计选择都解释成架构必然性。
- 在通常条件下，若不直接求解而采用梯度式更新，Quantile Balancing 还可以联系到原 loss-free 方法的数学形式。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=3637">分位数计算如何在巨大 batch 中落地</a> `1:00:37`

<details>
<summary>精确保存全部激活不可行，需要可扩展的近似统计实现。</summary>

- 大模型训练的 batch 可能达到数千万 token，若保存全部 token 的激活再精确求分位数，存储和计算都过于昂贵。
- 早期博客讨论过把大 batch 拆成小块，各自计算局部分位数，再汇总结果的做法。
- 孙宇涛对 K3 报告的理解是，不只沿 token 维度分块，而是在有界值域中划分若干桶，用 histogram 统计分布。
- 例如 sigmoid 输出位于 0 到 1，可以利用已知值域构造桶；存储量由桶数控制，而不必随 token 数线性增长。
- 这种方式更适合大规模分布式场景，也体现了数学方案必须配套工程实现。
- 他明确保留了理解上的不确定性，表示自己对该细节的解读可能有误，不能将其讲解当作作者的逐字实现说明。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=3745">为什么视觉编码器选择从头训练</a> `1:02:25`

<details>
<summary>已有编码器收敛快，但原生训练可能在兼容性和梯度稳定性上更好。</summary>

- 视觉部分讨论是否使用已有 ViT，例如 SigLIP 2，来初始化视觉编码器；成熟预训练编码器通常可加快收敛。
- K3 团队观察到，从已有编码器初始化时，梯度 norm 的尖峰或整体数值可能比原生训练更不理想。
- 孙宇涛提醒，稳定性不是一个单一、严格定义的指标，实际常通过 gradient norm 分布及尖峰等现象判断。
- 从零训练会消耗更多算力，但经过适当训练，最终效果并不一定更差，也可能相近或更好。
- 他将其联系到 Adam 与 Muon 之间切换微调的兼容性问题：原生一致的优化方式往往更顺畅，跨方案迁移可能需要额外处理。
- 他把 K3 的选择理解为追求整体训练的稳定与兼容，而不是宣称已有视觉编码器不可用。

</details>

## 稀疏注意力、混合架构与创新的边界

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=3844">不用稀疏注意力，要从实际收益解释</a> `1:04:04`

<details>
<summary>省掉注意力计算之前，先要付出找到稀疏索引的成本。</summary>

- 这里的问题是 K3 为何使用线性注意力与全注意力的混合，而未进一步加入 sparse attention，不是说 K3 是纯线性模型。
- 孙宇涛认为是否采用稀疏注意力，既取决于架构，也取决于 GPU 代际和硬件特性。
- 某些稀疏方案在 decode 中实际加速有限，因为先选择需要参与注意力计算的 token、求解 index，本身很昂贵。
- 在 Blackwell 等更快硬件上，基础计算已很高效，索引计算的相对开销可能更突出，不能只看减少了多少注意力项。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=3902">跨层复用索引，才能摊薄额外开销</a> `1:05:02`

<details>
<summary>Index Cache 和 YOCO 的相关探索都强调避免每层重复筛选。</summary>

- Index Cache 一类方法把索引计算结果在多层间共享，例如每四层或八层复用一次。
- 只有将索引开销压得足够低，稀疏注意力节省的计算才会转化为明显的端到端收益。
- 孙宇涛团队在 YOCO 上探索得更进一步：既然 KV Cache 共享一份，也让稀疏索引只计算一次，在更多层之间分摊。
- 这些经验共同说明，稀疏化的算法收益不能与索引和调度成本分开评价。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=3955">混合结构让稀疏化更不直接</a> `1:05:55`

<details>
<summary>全注意力层不相邻，而且当前稀疏转换与从头预训练并不完全兼容。</summary>

- K3 的全注意力层之间夹着多个线性注意力层，不能直接假定相邻全注意力模型里的 index sharing 仍然有效。
- 跨越这些线性层复用索引后，效果和加速比都需要额外验证。
- 孙宇涛指出，当前常见做法是把已训练的全注意力模型在后训练阶段转为稀疏形式，而非直接从零训练稀疏模型。
- 他不排除 K3 未来转换已有全注意力部分，但 MLA 的使用还可能增加兼容难度。
- 因此暂不采用稀疏注意力可以理解为控制风险并保留接口，而不是证明稀疏路线无价值。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=4037">混合比例是清楚的工程取舍</a> `1:07:17`

<details>
<summary>线性层更多通常更快，但接近无损能力需要保留足够全注意力。</summary>

- 提高线性注意力比例通常可以增加速度，但需要与模型能力保留程度一起衡量。
- 孙宇涛把约 3:1 的线性与全注意力比例视作一个已较常用、接近无损的工作点。
- 若坚持不用混合架构，就要寻找其他方案解决相同的成本问题，而不是凭空消除取舍。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=4083">Transformer 的忒修斯之船</a> `1:08:03`

<details>
<summary>组件持续被替换，是否仍算同一种范式并没有清晰边界。</summary>

- 张小珺感到 K3 更像融合旧工作寻找更优解，而非一次巨大范式变化；孙宇涛认为这种判断也涉及命名方式。
- 2017 年 Transformer 本就由注意力、残差连接和层堆叠等已有概念组合而成。
- 随着这些组件被逐项替换，现代模型与最初结构相似度下降，但业界仍习惯使用 Transformer 这个名字。
- 他用忒修斯之船说明，是否应改称新范式并不是单纯技术问题，不应因名称没变就否定具体改进。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=4157">单点研究与完整模型产品是两种验证</a> `1:09:17`

<details>
<summary>现代前沿模型需要把架构、数据、规模验证和工程全部跑通。</summary>

- 注意力、MoE、优化器和跨层连接都可以形成独立研究贡献；技术报告则更多呈现这些点的综合结果。
- 在过去的视觉时代，一个架构在 ImageNet 上取得好结果就可能形成重要成果；现在完整模型还要解决规模验证、数据与工程。
- 孙宇涛个人仍认为研究有效性有严格的局部验证标准，不必要求每篇研究都同时做成完整产品。
- K2 到 K3 的变化也包含公司战略：K2 先把约 1T 参数 base model 的训练管线和能力做稳，K3 再释放更多优化与创新。
- 他不据此推断架构团队突然改变；许多研究一直在做，差别在何时集成到哪一代模型。

</details>

## 预训练调度、Scaling 与长上下文

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=4341">WSD 为什么把数据调度与学习率放在一起</a> `1:12:21`

<details>
<summary>不同学习率阶段有不同学习行为，可以把更好的数据安排在更有效的阶段。</summary>

- 孙宇涛说明，预训练和后训练部分会选择公开报告中值得讨论的点，不对未披露的具体经验作额外推断。
- MiniCPM 的 WSD 思路不只是换一条学习率曲线，而是讨论 data schedule 与 learning-rate schedule 如何配合。
- 在相关实验中，WSD 与 cosine decay 可以取得相近最终结果，说明中间衰减轨迹未必是唯一决定因素。
- 但学习率下降的 cooldown 阶段，loss 往往下降更快，因此可以尝试把更多高质量数据放在这一阶段。
- 这种数据与学习率的联合安排，可能优于数据均匀混合、学习率安排也不区分阶段的方式。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=4501">WSD 的灵活性不是无条件的最优性</a> `1:15:01`

<details>
<summary>稳定阶段方便临时决定训练终点，但最优学习率仍与总 token 预算有关。</summary>

- WSD 的稳定阶段不预先绑定一个衰减终点，方便训练中途因策略变化、提前发布或延后发布调整 token 总量。
- 这使团队不必一开始就完全锁定训练预算，具有实际项目管理价值。
- 但孙宇涛提醒，最优学习率本身仍依赖训练 token 总数，较短与较长训练预算可能需要不同学习率。
- 因此可以任意延长训练，不等于延长后仍在最优设置上；WSD 的收益不能被理解为免除超参数调节。
- 改变最终 token 数也不只有 WSD 能做到，其他调度可以通过相应方式实现。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=4614">K3 为何回到 cosine decay</a> `1:16:54`

<details>
<summary>较少的可调变量，可能比看起来更新的调度更适合实际搜索。</summary>

- K3 报告选择 cosine decay，孙宇涛将其解释为更容易找到良好超参数设置。
- 简化讨论下，cosine decay 主要关注总训练 token 和最大学习率；WSD 还要确定 decay 阶段占比。
- 额外自由度不一定更好，也意味着更多调参工作和潜在交互。
- 在许多团队采用 WSD 的背景下，K3 选择经典方案，体现的是基于实验与易调性的取舍，而非追逐新方法名称。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=4658">如何理解 K2 到 K3 的 2.5 倍效率</a> `1:17:38`

<details>
<summary>这是整体训练方案的比较，不能未经控制变量就归因于单项架构。</summary>

- 总参数从 K2 的约 1T 增至 K3 的 2.8T，激活参数由约 32.6B 提高到约 104B，后者增长超过三倍。
- 报告给出 K3 相对 K2 约 2.5 倍的 scaling efficiency 改善。
- 孙宇涛提醒，比较中是否固定数据并不明确；他记得团队回应并非完全固定，且报告没有清楚说明这一点。
- 因此应把该结果理解为架构、training recipe 与数据策略共同变化后的综合收益，而非纯架构控制变量实验。
- 不同代模型使用不同数据并不奇怪，但解读效率数字时必须保留这一限制。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=4743">混合注意力中的 NoPE 为什么有价值</a> `1:19:03`

<details>
<summary>位置已由其他组件提供时，全注意力不一定还需要 RoPE。</summary>

- K3 原生支持约一百万 token 上下文，位置编码选择是其中值得讨论的一点。
- 传统全注意力模型使用 RoPE，扩展上下文长度时往往要重新调整相关参数，否则外推效果不佳。
- 在混合架构中，线性注意力、局部窗口等部分已经提供了位置信息，全注意力层不一定需要重复承担同样功能。
- 孙宇涛介绍相关研究提出，把这部分全注意力中的 RoPE 去掉，改为 NoPE，可能同时改善表现和长上下文扩展。
- NoPE 在长度变化时不需要修改同类位置编码参数，避免不同长度配置反复调节。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=4859">RoPE 的强项与长文检索并非一回事</a> `1:20:59`

<details>
<summary>孙宇涛强调近距离偏置与长上下文能力要区分，结论应放在具体架构中理解。</summary>

- 孙宇涛看到相关研究后很快复现，认为效果好且方案优雅；后来审稿时也给予很高评价。
- 他的解释是，RoPE 的重要作用包括 recency bias，对短上下文建模有用，不应简单把它等同于长上下文能力的来源。
- 在所讨论的混合注意力设置中，这种偏置可能妨碍长距离信息访问，去掉后直接外推效果反而更好。
- 相比之下，RoPE 扩长后只改参数而不继续训练，结果可能仍很差。
- 因此 K3 在相应全注意力部分采用 NoPE；这段讨论不是主张所有模型、所有位置都应无条件删除位置编码。

</details>

## 后训练：量化、多教师蒸馏与推理加速

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=4941">低精度训练放在哪个阶段</a> `1:22:21`

<details>
<summary>K3 先用较高精度做大规模训练，再在 SFT 引入 QAT，以控制项目风险。</summary>

- 不同团队选择不同：孙宇涛以 DeepSeek-V3 原生 FP8、后续 W4A8 路线作对照，说明没有唯一的精度引入时机。
- K3 先采用较高精度训练，在 SFT 阶段再引入低精度量化感知训练 QAT。
- 从项目管理角度，超大规模训练的行为难以提前完全验证，高精度路线可以减少一个额外的不确定因素。
- 从他的经验看，为获得低精度推理效果，不必一定从预训练第一步就采用低精度；经过足量适配后，后期引入也可能获得相近结果。
- 因此他把 SFT 阶段引入 QAT 理解为风险更低、未必损失最终能力的选择，而不是证明早期低精度训练没有效率价值。
- K3 的强化学习部分则延续 K1.5 到 K2.5 的许多成熟积累，本段没有逐一展开任务策略。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=5051">黑盒蒸馏与白盒蒸馏的边界</a> `1:24:11`

<details>
<summary>能否读取教师内部概率与状态，决定了可以采用什么蒸馏方式。</summary>

- 孙宇涛沿 MiniLLM 等研究解释 on-policy distillation，而非把它视为 K3 首创。
- 黑盒蒸馏只能通过 API 获得输入输出，拿不到教师模型本身及其内部状态。
- 白盒蒸馏能访问模型与推理过程中的状态，因此可以采用更细粒度的学习信号。
- 经典方式由教师生成答案，再通过 SFT 或 forward KL 等方式让学生学习教师结果。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=5117">让学生先做题，再由老师纠正</a> `1:25:17`

<details>
<summary>On-policy distillation 在学生自己的生成轨迹上学习，而非只模仿教师答案。</summary>

- MiniLLM 所强调的反向思路是由学生生成答案，再让教师对生成过程提供逐步纠正信号。
- 孙宇涛用教学作比：一种是听老师讲课，另一种是自己做题、写推理过程，再请老师指出哪里有问题。
- 该方式与 reverse KL 联系起来，后来常被称为 on-policy distillation。
- 它的重要价值是让学生在自己会走到的状态上得到反馈，而不只是学习教师理想轨迹。
- 最初的典型产品场景是用较大的 Pro 模型指导更便宜的 Flash 模型，改善小模型档位的能力与竞争力。
- 这套白盒细粒度方案不能直接照搬到只提供普通输入输出的黑盒 API。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=5208">多教师合并，简化后训练协作</a> `1:26:48`

<details>
<summary>把高度异构的奖励与训练策略，先变成较同构的专项教师模型。</summary>

- 后来许多团队不只是做大模型到小模型蒸馏，也用相同基础模型的专项版本来教一个统一模型，即所谓自己蒸馏自己。
- 预训练可以相对直接地汇总数据，但后训练往往涉及复杂且不相同的训练策略，直接合并更难。
- 数学任务可能使用可验证奖励，偏好任务需要 reward model，其他能力又有各自的奖励和强化学习方式。
- 把这些异构奖励与流程直接放进同一次训练并非绝对不可能，但技术和组织管理都更复杂。
- 多教师方法让各团队先把专项能力做成模型，再用统一蒸馏方式合并能力。
- 教师模型通常具有相近架构，比奖励、数据和 RL 策略更同构，因此合并接口更简单。
- 孙宇涛认为这已经是较广泛接受的业界方法，不是 K3 独有的新概念。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=5360">单用户速度与总体吞吐不是一个目标</a> `1:29:20`

<details>
<summary>高 token/s 方案通常有特定硬件、batch 和成本条件，不能泛化为所有服务都更划算。</summary>

- 孙宇涛认为 K3 的推理加速仍有改进空间，并提到小米展示过约 1000 token/s 的方案作为延伸讨论。
- 他将该类速度归因于更深度的算子融合与投机推理叠加，而非单一模型结构。
- 这类方案更适合愿意付出更高成本、追求更低单用户延迟的需求。
- 在小 batch 场景中优势明显，不代表面对大量并发用户、追求整体吞吐时仍有相同收益。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=5421">从独立小模型到利用大模型中间状态</a> `1:30:21`

<details>
<summary>EAGLE、MTP 等方案让草稿模型与目标模型更紧密配合，提高接受率。</summary>

- 早期 speculative decoding 常用一个相对独立的小模型替大模型生成草稿，难以充分利用大模型已计算的 hidden state。
- 若草稿模型可访问目标模型的中间状态，就可能做得更小，或在同样参数下获得更高接受率。
- EAGLE 3、MTP 等方法体现了这种思路，通过更紧密的配合改善整体推理效率。
- 孙宇涛还讨论 DFlash，将 diffusion language model 的并行生成思路用于草稿与投机加速。
- 纯扩散语言模型从零训练的效率和最终能力仍有挑战，而且优势更偏向单用户、小 batch 速度，不必然适合多用户总吞吐。
- 把扩散式生成用于草稿，是尝试结合其速度与传统自回归模型能力，而非简单替换整个基础模型。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=5534">草稿模型的能力也需要预训练配合</a> `1:32:14`

<details>
<summary>高效推理不是最后外挂一个小模块，预训练接口与专门目标都很重要。</summary>

- 即使采用更先进的草稿模型，仍要利用基础模型已有能力，因此与预训练的联系很强。
- 孙宇涛转述相关讨论称，在预训练阶段为 MTP 预留合适接口，会明显帮助下游草稿模型。
- 草稿模型也需要专门训练，例如使用 KL loss 替代单纯 next-token prediction，使输出更贴近目标模型。
- 这种对齐有助于提高目标模型验证时的接受率；孙宇涛认为这里仍有进一步研究空间，但明确这是他的判断。

</details>

## Infra 协同：上下文并行与分布式训练

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=5609">架构选择会改变整套 Infra</a> `1:33:29`

<details>
<summary>K3 的工程方案并非独立附件，很多差异源于模型本身的不同。</summary>

- 孙宇涛强调两种关系：架构必须与 Infra 共同设计，架构选型也会反过来决定整个工程系统的形态。
- KDA 对衰减系数的限制，就是为了获得更高效 kernel 的具体例子。
- K3 与 DeepSeek 等模型在并行和通信上采用不同策略，不能只按某一个工程技巧的名气比较优劣。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=5649">线性注意力的上下文并行</a> `1:34:09`

<details>
<summary>分块大小不改变数学结果，使块递归能够扩展成多级并行。</summary>

- 全注意力的上下文并行 CP 可以通过分布式交换所需 K/V 完成；线性注意力的状态递推使概念更复杂。
- 单机块递归通常在较小 chunk 内并行计算，在 chunk 之间递归传递状态。
- 对纯线性注意力计算，使用 512-token 或 8K-token chunk 在数学上可以等价，块大小主要是实现选择。
- 这不同于块内全注意力、块间线性注意力的拼接式架构，后者的块大小本身会改变模型定义。
- 因此可以先把一百万 token 长序列按较大块分配到多张 GPU，再把每张卡内的大块继续分成 kernel 适合的小块。
- 机器间和 kernel 内构成两级 chunk，都是同一块递归思想，不必限制为只分块一次。
- 这种自由重分块的性质，是 KDA/线性注意力构造 CP 方案的重要基础。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=5848">Dropless EP 的两类开销</a> `1:37:28`

<details>
<summary>不丢 token 保住能力，却让每卡负载和通信规模都变得不固定。</summary>

- 传统 dropless 专家并行允许 token 自由选择专家，不通过丢 token 强行满足固定容量。
- 汇总后不同专家、不同 GPU 获得的 token 数不一致，执行时长也不同，快卡等待慢卡造成浪费。
- 通信前还要先告知接收方将收到多少 token，再传输实际数据，增加一个准备阶段。
- 从纯 Infra 角度，固定且均衡的工作量更理想，但通过丢 token 强制均衡会损害模型能力。
- 因此目标是在保留路由结果和能力的同时，让硬件执行尽量接近均衡。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=5967">MoonEP 用冗余专家实现卡级均衡</a> `1:39:27`

<details>
<summary>动态规划专家副本的位置，而不是强迫每个专家收到同样数量的 token。</summary>

- 静态 EP 可以把 128 个专家均匀放到八张卡，每卡 16 个，但专家数量相等不代表实际 token 负载相等。
- MoonEP 引入少量冗余专家副本，以动态方式分配工作。
- 孙宇涛介绍，相关方案可以证明存在一种分配策略，用少量冗余使各卡 token 数对齐。
- 具体通过 online planning 规划哪些 GPU 放哪些冗余专家，改善不同卡之间的负载。
- 必须区分卡级均衡与专家级均衡：每卡总 token 数相同，并不意味着每个专家的 token 数相同。
- 若还要求每个专家完全等量，往往需要约束路由或引入有损策略；该方案的目标并非消除所有层次的不均衡。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=6063">FP8 Offloading 要满足带宽条件</a> `1:41:03`

<details>
<summary>把激活转移到 CPU 并非天然免费，关键是传输能否被计算覆盖。</summary>

- K3 在软件层面更细粒度地控制各组件的激活存储、重计算与 offloading 策略。
- 它较大规模地将中间计算结果卸载到 CPU，以缓解 GPU 显存压力。
- 若 CPU 与 GPU 通信太慢，offloading 会拖慢训练；只有满足相应带宽与计算时间关系，才可能用计算覆盖传输。
- K3 将可卸载内容用 FP8 存储，减少约一半传输与存储量，有可能跨过可被隐藏的性能边界。
- 边界取决于具体 GPU、集群和模型配置，不能脱离硬件条件断言同样做法总是有效。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=6128">为什么 K3 可以用更简单的通信重叠</a> `1:42:08`

<details>
<summary>LatentMoE 先减少通信量，使共享专家计算足以隐藏更多开销。</summary>

- 传统 MoE 的 dispatch 和 combine 都有显著通信成本，DeepSeek-V3 采用细粒度拆解、跨 microbatch 重排前反向计算来隐藏这些开销。
- 这种方式需要把计算拆得很细并手动安排执行次序，工程实现复杂。
- DeepSeek 的 DualPipe/DualPipeV 还通过流水线布局缓解气泡和激活不均衡；K3 公开方案没有照搬这两项设计。
- K3 使用 LatentMoE 后通信量较小，可以在同一 batch 内，将 MoE 通信与 shared expert 计算重叠。
- 共享专家本来就有计算工作；通信降低到足够小后，便可用这部分工作覆盖，而不必拉入另一批次。
- 传统 MoE 通信量更大，同样的共享专家计算未必够用，因此才需要更复杂的跨批次调度。
- 即使通信时间表面被完全覆盖，通信与计算仍可能争抢资源；减少通信量本身仍有价值。
- DeepEP 等库也会优化 SM 占用，以尽量少的计算资源维持较高通信吞吐，降低重叠时对计算的影响。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=6354">流水线显存与 Muon 分片</a> `1:45:54`

<details>
<summary>保持简单流水线，但用状态转移和矩阵级分片处理其不均衡。</summary>

- 单向 pipeline parallelism 中，前面的 rank 更早进入流水线，可能积累更多未完成 batch 的激活，显存压力更大。
- K3 将显存占用较大的 rank 上部分状态转移到后续较空闲 rank，以较轻量方式缓解不均衡，而非完全改用对称流水线。
- Muon 的 Newton-Schulz 迭代需要完整矩阵信息，与 Adam 的逐元素更新不同。
- Adam 可把参数摊平后较自由地分片，而 Muon 需要让相应 rank 获得完整矩阵，因此分布式参数切分需专门适配。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=6432">视觉编码器可能比语言主干更需要 CP</a> `1:47:12`

<details>
<summary>送进语言模型前的视觉 token 压缩，不能省掉编码器内部的原始计算。</summary>

- 孙宇涛认为每增加一种多模态功能，Infra 优化难度都会显著提高。
- 例如输入语言模型时视觉序列可能已压成 8K token，但编码器内部此前仍需处理约 32K 的视觉表示。
- 因此即便语言主干无需开启上下文并行，视觉编码器也可能因序列更长而需要 CP。
- 这种不同组件具有不同并行需求的情况，要求工程系统做额外适配，而非给整个模型套同一组并行配置。

</details>

## 多模态与推理服务的工程细节

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=6501">视觉编码器的放置会改变流水线负载</a> `1:48:21`

<details>
<summary>视觉 token 比例不均不仅影响数据并行，也会让流水线出现新的瓶颈；K3 利用后续阶段的空闲时间提前处理视觉计算。</summary>

- 嘉宾提醒，同一批多模态数据在不同卡上的组成可能相差很大：有的卡处理纯文本，有的卡视觉 token 占比很高。因此即使序列长度相近，实际工作量仍可能不均衡。
- 这种差异不仅影响数据并行，也影响流水线并行。流水线要尽量填满，各阶段的计算量就需要相对接近；如果把新增的视觉编码器全部放在第一阶段，第一阶段会明显变重，拖慢整个流水线。
- 按嘉宾对报告的解读，K3 没有简单把视觉编码器都堆在最前面的流水线阶段，而是利用中间或后面的阶段来承担相关计算。前面的浅层语言模型工作时，后续阶段原本可能闲置，可以提前计算视觉处理的部分步骤。
- 这种调整针对的是流水线气泡，而不是改变模型语义。重点是识别哪些计算能够提前执行，以及哪些设备此时空闲，让新增视觉工作不再集中阻塞第一阶段。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=6570">公开工程细节比传播小道消息更有价值</a> `1:49:30`

<details>
<summary>嘉宾认为基础设施实现具有较高确定性，但独立发现好方案仍依赖分析能力、人才密度和团队氛围。</summary>

- 主持人感叹报告对工程实现写得很细。嘉宾回应，这些问题在真正训练时都必须处理，只是方案写出来之后，读者容易觉得理所当然。
- 当关键细节没有公开、团队又缺少独立解决问题的能力时，人们容易转向私下打听。把方法清楚写出来，可以减少对小道消息的依赖，让讨论建立在可检验的工程实践上。
- 谈到复现难度，嘉宾认为这一类基础设施工作本身具有较高确定性，已知方案的实现与从零发明方案不是同一个难度。他没有把复现说成无需投入，而是在区分工程落地和独立发现瓶颈的能力。
- 要自己提出这些优化，需要扎实的 profiling、对性能问题的分析能力，以及足够的人才密度和适合做工程研究的团队氛围。尚不能独立提出方案的团队，也应当能够跟进公开的优秀实践。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=6631">强化学习基础设施还要管理大量执行环境</a> `1:50:31`

<details>
<summary>除了预训练和推理，RL 还有大规模沙箱调度这一类独立的工程难题。</summary>

- 嘉宾将基础设施讨论分为预训练、强化学习和推理三部分。此前主要讨论预训练中的大规模分布式优化，而 RL 本身包含大量推理，所以它与推理服务存在明显重叠。
- RL 又有不同于一般推理服务的需求：任务执行可能需要独立的沙箱，每条 trajectory 都可能对应自己的 Docker 容器。此时系统不仅要运行模型，还要管理大规模的执行环境。
- 因此 RL 的难点不只是模型吞吐，也包括如何组织、调度和管理大量沙箱。嘉宾把这部分定位为细致的工程工作，没有在本段展开具体调度算法。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=6676">按生命周期复用参考模型和梯度缓冲区</a> `1:51:16`

<details>
<summary>参考模型与梯度缓冲区并不总要同时存在，利用使用时间错开可以节省显存。</summary>

- 嘉宾认为 K3 报告里复用梯度缓冲区的做法很有意思，同时明确保留了原创性判断：他并不确定这一方法最初是否由 K3 提出。
- 完整 RL 训练可能同时涉及主模型、参考模型、主模型的梯度和优化器状态，有时还包括奖励模型。这些对象都要占用显存，因此节省一整块模型或梯度缓冲区就可能带来显著收益。
- 报告中的关键观察是，参考模型不需要计算梯度；在用它计算目标相关信息时，主模型的梯度还未产生。等到梯度产生并需要存储时，参考模型在这一阶段又可能已经不再使用。
- 因此可以让参考模型占用的内存与梯度缓冲区复用同一块空间，利用两者生命周期错开来减少峰值占用，而不是简单要求所有模型和缓冲区永久同时驻留。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=6744">混合注意力要求新的缓存管理方式</a> `1:52:24`

<details>
<summary>线性注意力会覆写状态，不能直接套用逐 token KV 缓存；分块保存状态并适配异构层，是进入现代推理引擎的必要工作。</summary>

- 嘉宾没有逐一展开通用推理优化，而是将 vLLM、SGLang 等引擎视为主要承载者，重点看 K3 架构为现有引擎带来了哪些新增适配工作。
- 全注意力的 KV 缓存通常随新 token 追加，新的前缀可以看作旧前缀加上增量，因此复用已有前缀较直接。线性注意力则在上一步状态上进行更新和覆写，不同前缀对应的是不同的状态快照。
- 若保存线性注意力每一步的全部状态，会削弱它节省存储的优势；若完全不保存历史状态，又无法享受前缀缓存带来的收益。报告所述思路是按 block 保存状态，在存储开销与前缀复用之间折中。
- 嘉宾指出，早期推理引擎最简单的 KV 管理方式通常没有充分考虑不同层使用不同注意力形式。把混合架构直接塞进越来越复杂的引擎并不容易，零散补丁还可能让系统变得混乱。
- 全注意力的逐 token 分页管理不能原样套在持续覆写状态的线性注意力上；滑动窗口等形式也有不同的存储生命周期。支持混合模型，需要让引擎正确管理不同注意力模式的缓存。
- 此外，解码、prefill 与训练的性能特点不同，各环节都需要对应的适配与优化。嘉宾认为这些事情可以通过确定性较高的工程工作解决，但不能因为架构公式成立就省略实现环节。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=6895">最意外的是敢于把激活规模做大</a> `1:54:55`

<details>
<summary>嘉宾认为 K3 最超出预期的是规模选择，而不是某个突然出现的新技巧；成果来自长期积累被有效放大。</summary>

- 对于报告末尾的评测，嘉宾只给出整体表现很好的评价，没有在节目中逐项解释榜单或具体分数，因此本段的重点转向他对 K3 的总体判断。

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=6987">研究是否科学，也取决于组织如何作判断</a> `1:56:27`

<details>
<summary>可靠追踪、故障归因和控制变量只是基础；团队是否愿意按证据而不是局部利益决策，同样关键。</summary>

- 主持人询问 Kimi 的研究方式是否更科学，嘉宾表示认可，并将这种印象部分归因于内部管理方式，而不只是某个具体技术方法。

<details>

- 在比较 K3 与 DeepSeek V4 时，嘉宾先强调两者定位和基础设施选择差异较大，并非完全相同的产品，不能把所有维度压成单一输赢。

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=7147">有效扩展依靠团队，而不只是模型参数</a> `1:59:07`

<details>
<summary>规模带来的能力变化需要全链路实现；技术创新发生在让更大模型真正可训练、可用的过程中。</summary>

- 嘉宾区分“有哪些架构创新”和“是否成为里程碑”：前者可以逐项讨论，后者最后仍主要由整体能力变化决定，不能只数技术报告里有多少新技巧。
- 他以 DeepSeek 过去的进展为例，强调把模型扩展到较高水平并打通强化学习的重要性；在他看来，综合能力跨过一个层级，比孤立看某个算法名称更重要。
- 回到 K3，他认为激活规模和整体规模显著增加，使模型有机会进入下一个能力层级。这里的核心不是无条件相信越大越好，而是让扩展真正转化为有效能力。
- 把若干配置数值调大很容易，但那并不自动解决训练稳定性、系统效率或最终效果。扩大规模这个动作本身不是创新，让放大的模型工作起来才需要贯穿架构与工程的创新。
- 因此这一结果是集体工作，不应被理解为某个人靠一个聪明想法独立完成。前面讨论过的训练、通信、显存和推理优化，都是有效扩展得以成立的组成部分。

</details>

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=7220">新团队的机会取决于人才与组织同时成立</a> `2:00:20`

<details>
<summary>理论上仍有进入机会，但优秀个体、良好氛围和合适领导方式同时出现并不容易。</summary>

- 对于现在新组团队重做大模型是否还有机会，嘉宾给出条件式回答：如果团队足够好、氛围足够好、成员能力足够强，机会仍然存在；但他认为这些条件同时满足的概率很低。
- 他没有简单把困难归结为“好人才已经被招走”，而是强调优秀的人与能够组织这些人的领导者相遇具有历史条件，不是想搭建就一定能搭建出来。

- 这也再次指向同一结论：大模型研发是高度集体化的工作，不依赖个人英雄主义，组织能否让不同人的能力形成合力非常重要。

### <a href="https://www.bilibili.com/video/BV1KZ8X6uEPL/?t=7279">先把能力定义清楚，再讨论 AGI 和规模上限</a> `2:01:19`

<details>
<summary>嘉宾预计语言模型仍会扩大，但更看好持续改良；他对可清晰定义的语言任务较乐观，对真实物理交互保留更大距离判断。</summary>

- 谈到半年或一年后的趋势，嘉宾预计模型规模还会继续增加，同时将“大模型可能没有太多根本性创新，后续主要是改良”明确作为自己的较强个人判断，而非已经证实的事实。
- 他认为讨论未来能力首先要定义任务：研究或商业上究竟重视什么、怎样衡量成功。对纯语言范围内能够清楚定义的能力，他对持续优化最终达到目标较为乐观。
- 对于 AGI，他认为主要问题之一是缺少良好定义；如果只是笼统使用这个词，很难判断是否达到。若定义包含具身智能或与真实物理世界的交互，他承认现有系统仍存在更大的差距。
- 他不认为模型规模会无限增长，因为可用于预训练的人类互联网信息是有限的。要吸收有限信息，不需要无限大的模型；但具体任务的复杂度又会影响所需规模。
- 未来若出现更难的任务，可能需要更大模型，当前模型也仍有继续做大的空间。不过他没有给出最终参数上限，并明确表示对更远处的规模无法确定。
